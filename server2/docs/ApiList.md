# API の分類（呼び出し元ごとの種類数）

`server2` の仕様書で定義済みの API を、呼び出し元ごとに分類したもの。個々の API の仕様は、各仕様書を参照する。

- クライアントアプリ向け：ApiSpec_Auth.md（#1〜#31）、ApiSpec_TestData.md（#32〜#35）
- 運用担当者・所属向け：ApiSpec_Belonging.md（B1〜B21・B27〜B29）、ApiSpec_TestData.md（B22〜B26）

## 1. 呼び出し元ごとの種類数

| 呼び出し元 | API の種類数 | 仕様書 | パス |
|---|---|---|---|
| **クライアントアプリ**（家族・ユーザが使うアプリ） | **35種類** | ApiSpec_Auth.md #1〜#31、ApiSpec_TestData.md #32〜#35 | `/api/v1/...` |
| **運用担当者・所属が使うアプリ** | **29種類** | ApiSpec_Belonging.md B1〜B21・B27〜B29、ApiSpec_TestData.md B22〜B26 | `/api/v1/blg/...` |
| 合計（定義済み） | 64種類 | | |

運用担当者・所属向けの29種類の内訳：

| 区分 | 種類数 | 内容 |
|---|---|---|
| 運用担当者と通常の所属の**両方**が使う | 14種類 | B1、B4〜B7、B12〜B16、B22〜B25 |
| **運用担当者のみ**が使う | 15種類 | B2、B3、B8〜B11、B17〜B21、B26〜B29 |

## 4. 補足

- 上の分類は、仕様書の記述（パス、認証の種類、対象者）から整理したもの。
- クライアントアプリ向けには、**認証が不要な画面**の API（登録・ログイン・招待の照合：#1〜#4、#28）も含まれる。登録ページ・招待ページも、同じクライアントアプリの画面として数えている。
- 2つの呼び出し元で、共通の API はない。認証の Cookie も別である（家族：`__Host-sid`、所属：`__Host-blg-sid`）。
- 運用担当者向けの API の権限は、サーバ側でも検証する（運用担当者の所属以外が呼ぶと `403 SUPER_ONLY`）。画面の表示だけに頼らない。
- 現行の `server/`（CSV 方式、実装済みの6種類）は、本書の対象外である。
