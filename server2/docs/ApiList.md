# API の分類（呼び出し元ごとの種類数）

`server2` の仕様書で定義済みの API を、呼び出し元ごとに分類したもの。個々の API の仕様は、各仕様書を参照する。

- クライアントアプリ向け：ApiSpec_Auth.md（#1〜#31）、ApiSpec_TestData.md（#32〜#35）
- 運用担当者・組織向け：ApiSpec_Organization.md（O1〜O21）、ApiSpec_TestData.md（O22〜O26）

## 1. 呼び出し元ごとの種類数

| 呼び出し元 | API の種類数 | 仕様書 | パス |
|---|---|---|---|
| **クライアントアプリ**（家族・ユーザが使うアプリ） | **35種類** | ApiSpec_Auth.md #1〜#31、ApiSpec_TestData.md #32〜#35 | `/api/v1/...` |
| **運用担当者・組織が使うアプリ** | **26種類** | ApiSpec_Organization.md O1〜O21、ApiSpec_TestData.md O22〜O26 | `/api/v1/org/...` |
| 合計（定義済み） | 61種類 | | |

運用担当者・組織向けの26種類の内訳：

| 区分 | 種類数 | 内容 |
|---|---|---|
| 運用担当者と通常の組織の**両方**が使う | 14種類 | O1、O4〜O7、O12〜O16、O22〜O25 |
| **運用担当者のみ**が使う | 12種類 | O2、O3、O8〜O11、O17〜O21、O26 |

## 4. 補足

- 上の分類は、仕様書の記述（パス、認証の種類、対象者）から整理したもの。
- クライアントアプリ向けには、**認証が不要な画面**の API（登録・ログイン・招待の照合：#1〜#4、#28）も含まれる。登録ページ・招待ページも、同じクライアントアプリの画面として数えている。
- 2つの呼び出し元で、共通の API はない。認証の Cookie も別である（家族：`__Host-sid`、組織：`__Host-org-sid`）。
- 運用担当者向けの API の権限は、サーバ側でも検証する（運用担当者の組織以外が呼ぶと `403 SUPER_ONLY`）。画面の表示だけに頼らない。
- 現行の `server/`（CSV 方式、実装済みの6種類）は、本書の対象外である。
